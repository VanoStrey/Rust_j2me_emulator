## 2. Доказательная база по каждому дефекту

### SEC-01: Reflected Cross-Site Scripting (XSS) в `/issue/:id`
- **Репозиторий:** `j2me_market`
- **Файл:** `server_rust/src/router.rs` (строки 1170–1185), `server_rust/src/ssr.rs`
- **Механизм:** Несанитизированное значение `raw_id` интерполировалось в `page_title`, `page_url` и JSON-строку `<script>window.INITIAL_ROUTE = {route_json};</script>`.
- **Воспроизведение:** Запрос `GET /issue/%3C/script%3E%3Cscript%3Ealert(1)%3C/script%3E` приводил к закрытию тега `<script>` в HTML-парсере браузера и выполнению введенного скрипта.
- **Ожидаемый результат:** Отклонение запроса с кодом 404/400 и полное экранирование метатегов.
- **Влияние:** Возможность кражи сессионных данных, локальных сохранений и выполнение действий от имени пользователя.
- **Серьезность:** P1 (High).
- **Уверенность:** **PROVEN**.
- **Исправление:** Добавлен regex/длина-валидатор формата номера выпуска `issue_XXX` в `router.rs` и экранирование `escape_html` / `<\/` в `ssr.rs`. Добавлен регрессионный тест `test_ssr_xss_prevention_in_title_and_meta`.

### VM-01: Strict Mode не влиял на ядро виртуальной машины
- **Репозиторий:** `Rust_j2me_emulator`
- **Файлы:** `crates/j2me-core/src/vm/interpreter.rs`, `crates/j2me-stdlib/src/emulator.rs`
- **Механизм:** Метод `handle_athrow` в `interpreter.rs` проверял только `if thread.call_stack.len() > 1`, безусловно запуская Auto-Healing (снятие фрейма и возврат фиктивного нуля). Флаг `strict_mode` присутствовал только в `context` stdlib и не передавался в `j2me-core`.
- **Воспроизведение:** Вызов `emu.set_strict_mode(true)` не предотвращал подавление ошибок в глубоких фреймах.
- **Ожидаемый результат:** В строгом режиме виртуальная машина обязана следовать стандарту JVM и завершать поток вызовом `UnhandledException`.
- **Влияние:** Скрытие фатальных ошибок, искажение отчетов совместимости.
- **Серьезность:** P1 (High).
- **Уверенность:** **PROVEN**.
- **Исправление:** Добавлен флаг `strict_mode: bool` в `GreenThread` и `Scheduler`, добавлена проверка `if !thread.strict_mode && thread.call_stack.len() > 1` в `handle_athrow`, добавлено каскадное обновление потоков в `emulator.set_strict_mode`. Написан тест `test_strict_mode_prevents_auto_healing_and_returns_unhandled_exception`.

### PY-01: Ошибка импорта `List` в `run_market.py`
- **Репозиторий:** `j2me_market`
- **Файл:** `run_market.py` (строки 37 и 87)
- **Механизм:** В строке 87 объявлена аннотация `VAULT_GAMES: List[Dict[str, Any]] = []`, но в строке 37 `List` не был импортирован из модуля `typing`.
- **Воспроизведение:** `python3 -c "import run_market; print(run_market.__annotations__)"` падал с `NameError: name 'List' is not defined`. В Python < 3.14 запуск сервера падал на старте.
- **Ожидаемый результат:** Безошибочный импорт и запуск во всех поддерживаемых версиях Python (3.9–3.14).
- **Влияние:** Отказ запуска локального сервера разработки на стандартных дистрибутивах Linux (Debian 12 / Ubuntu 22.04).
- **Серьезность:** P1 (High).
- **Уверенность:** **PROVEN**.
- **Исправление:** Добавлен `List` в строку импорта `typing`. Добавлен тест целостности аннотаций в `scripts/test_unit.py`.

### VM-02: Утечка буфера аудио в `j2me_wasm.js`
- **Репозиторий:** `j2me_market`
- **Файл:** `market_ui/wasm/j2me_wasm.js` (строка 280)
- **Механизм:** При каждом вызове `emu_load_jar` происходило выделение `wasmExports.emu_alloc_buffer(4096 * 4)` без вызова `emu_free_buffer` для старого указателя.
- **Воспроизведение:** Запуск 100 игр подряд приводил к накоплению 1.6 МБ неудаляемых буферов в куче WASM.
- **Ожидаемый результат:** Освобождение старого буфера перед выделением нового.
- **Влияние:** Постепенное фрагментирование и исчерпание памяти WASM.
- **Серьезность:** P1 (High).
- **Уверенность:** **PROVEN**.
- **Исправление:** Добавлен вызов `wasmExports.emu_free_buffer(audioBufferPtr, 4096 * 4)` перед аллокацией.
