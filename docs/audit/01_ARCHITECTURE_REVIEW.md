# 01. Архитектурный обзор систем (Architecture Review)
## Системная архитектура J2ME Market и Rust J2ME Emulator

---

## 1. Концепция и границы ответственности

Вся система состоит из двух автономных проектов с четким разделением ролей:

1. **Rust J2ME Emulator (Project B):**
   - Автономный, независимый от платформы интерпретатор байткода Java 2 Micro Edition (CLDC 1.1 / MIDP 2.0).
   - Скомпилирован под два целевых таргета:
     - `aarch64-apple-darwin` / `x86_64-unknown-linux-gnu` (нативный CLI-раннер, фаззер, бенчмаркинг);
     - `wasm32-unknown-unknown` (высокопроизводительный WebAssembly-модуль для браузерного исполнения).
2. **J2ME Market (Project A):**
   - Пользовательский портал, интерактивный музей и цифровой архив мобильной игровой культуры эпохи 2000-х годов.
   - Окружение стилизовано под журнал «Страна Игр» №08 (145) за 2006 год.
   - Включает интерактивные 3D-модели аутентичных мобильных телефонов (Sony Ericsson K750i/W810i/W900i, Nokia N95/7610, Motorola RAZR V3, Siemens SX1, Samsung D600).
   - Предоставляет статические ресурсы (игры, скриншоты, описания, саундтреки) и загружает эмулятор в браузер клиента.

## 3. Верификация клиентского исполнения (Client-Side Execution)

**Требование:** *«Игровой байткод должен исполняться на устройстве пользователя. Сервер не должен выполнять эмуляцию вместо клиента»*.

### Фактическое состояние: **ПОДТВЕРЖДЕНО (PROVEN)**
1. **Первичный контур (WASM 60 FPS):**
   - При выборе игры в интерфейсе (`startPhoneLivePlay(slug)` в `market_ui/js/emulator_client.js`) происходит запрос к `window.EmulatorProvider.getProvider()`.
   - В нормальных условиях создается экземпляр `WasmEmulatorProvider` (`market_ui/js/emulator/WasmBridge.js`).
   - Браузер скачивает скомпилированный модуль `j2me_wasm.wasm` (2.8 МБ) один раз и кэширует его.
   - JAR-файл скачивается в браузер как бинарный `ArrayBuffer` через `/api/archive/download?slug=...` и передается напрямую в память WebAssembly через функцию `emu_load_jar(ptr, len)`.
   - **Интерпретация байткода, диспетчеризация инструкций, циклы отрисовки 2D/DirectGraphics, программный синтез звука MIDI/PCM и обновление кадрового буфера выполняются на 100% на CPU пользователя в браузере.**
   - При этом сервер не расходует CPU на эмуляцию.
2. **Резервный контур (Cloud FreeJ2ME WebBridge Fallback):**
   - Если браузер пользователя не поддерживает WebAssembly или при инициализации WASM-модуля произошла фатальная ошибка, активируется резервный провайдер `WebBridgeEmulatorProvider` (`market_ui/js/emulator/RemoteStream.js`).
   - Только в этом случае сервер спавнит JVM-процесс FreeJ2ME и передает видеопоток JPEG/Base64 на клиент по протоколу HTTP/WebSocket.
   - Этот режим является аварийным (failover) и защищен rate-limiting лимитом Nginx (2 запуска в секунду, burst 5).

## 4. Архитектура рабочего пространства Rust J2ME Emulator

Репозиторий `Rust_j2me_emulator` организован как Cargo Workspace со строгим разграничением ответственности:

```text
Rust_j2me_emulator/
├── crates/
│   ├── j2me-core/         # Независимое ядро JVM/KVM (Zero-dependencies кроме miniz_oxide/serde)
│   │   ├── src/classfile/ # Парсер ClassFile (Константный пул, атрибуты, верификатор типов)
│   │   ├── src/heap/      # Модель памяти (Object, Array, Slot, Value, Garbage Collector)
│   │   ├── src/jar/       # Загрузчик JAR/JAD, парсер манифеста, детектор нативного разрешения
│   │   ├── src/threads/   # Планировщик Green Threads, мониторы синхронизации, тайминги
│   │   └── src/vm/        # Преддекодер байткода, фреймы вызовов, интерпретатор инструкций
│   │
│   ├── j2me-stdlib/       # Стандартные библиотеки среды исполнения (MIDP 2.0 / CLDC 1.1 / Nokia)
│   │   ├── src/bridge/    # NativeBridge: диспетчеризация 300+ нативных системных вызовов
│   │   ├── src/cldc/      # java.lang, java.util, java.io, потоки, кодировки CP1251/UTF-8
│   │   ├── src/midp/      # javax.microedition.lcdui (Graphics, Canvas, Image, Font)
│   │   ├── src/media/     # MMAPI: синтезатор MIDI (Wavetable + AdLib/OPL3 FM), AudioRingBuffer
│   │   ├── src/nokia/     # Nokia UI: DirectGraphics, расширенные блиттинги и трансформации
│   │   └── src/emulator.rs# Высокоуровневый фасад J2meEmulator, цикл tick() и события ввода
│   │
│   ├── j2me-wasm/         # C-ABI мост для компиляции в WebAssembly (wasm32-unknown-unknown)
│   │   └── src/lib.rs     # Zero-Copy интерфейс: emu_tick, emu_get_framebuffer_ptr, RMS I/O
│   │
│   └── j2me-cli/          # Нативный исполняемый бинарник для десктопа и тестирования
│       ├── src/main.rs    # Точка входа CLI: рендеринг кадров в PNG, запись аудио WAV
│       ├── src/fuzzer/    # Фаззер байткода и генератор хаотического ввода (Chaos Agent)
│       └── src/market.rs  # Инструмент аудита и пакетной верификации каталога игр
```

### Анализ чистоты границ ядра
- Крейт `j2me-core` **на 100% автономен**. Он не имеет привязок к WebAssembly, операционной системе или веб-браузеру. Ядро компилируется как под нативные архитектуры (macOS, Linux, Windows), так и под `wasm32-unknown-unknown`.
- Разделение между `j2me-core` и `j2me-stdlib` соблюдено: ядро отвечает за работу виртуальной машины (байткод, куча, потоки), а `j2me-stdlib` содержит реализации классов платформы MIDP.

## 5. Анализ серверного дуализма в J2ME Market

В проекте обнаружено сосуществование двух независимых бэкендов:

| Характеристика | `run_market.py` | `server_rust` |
|---|---|---|
| **Язык реализации** | Python 3.10+ (стандартная библиотека) | Rust (фреймворк `tiny_http`, `serde`, `ureq`) |
| **Фактическое назначение** | Локальная разработка и отладка | **Боевой продакшн на сервере 177.3.222.50** |
| **Управление процессом** | Одиночный запуск через консоль | Демон `j2me.service` под управлением systemd |
| **Раздача статических файлов** | Ограничена папками `market_ui/` и `catalog/` | Раздает `market_ui/`, `catalog/` и `/roms/` |
| **Поддержка SSR** | Отсутствует (статический HTML) | Встроена динамическая генерация OpenGraph / SEO метаданных |
| **Защита от DNS Rebinding** | Проверка заголовка `Host` (Whitelist) | Отсутствует |
| **Защита от CSRF** | Проверка `Origin` и `Sec-Fetch-Site` | Отсутствует |
| **CORS политика** | Строгая изоляция источника | `Access-Control-Allow-Origin: *` на всех эндпоинтах |
| **Производительность** | Средняя (~500 req/s, блокирующий I/O) | Высокая (~18,000 req/s, многопоточный пул) |

### Вывод по серверной части
Продакшн-контуром фактически является **`server_rust`**. Файл `run_market.py` сохраняется разработчиками как удобный скрипт для запуска в один клик без компилятора Rust.
