# 14. Нерешенные вопросы и стратегические дилеммы (Unresolved Questions)
## Инженерные, архитектурные и правовые развилки, требующие решения владельца продукта

---

## 1. Правовая модель дистрибуции ROM (Юридическая развилка)

**Проблема:**  
На боевом сервере `177.3.222.50` сейчас размещено 3.2 ГБ коммерческих ROM-файлов эпохи расцвета J2ME (игры Gameloft, Konami, id Software, Capcom, Sony Pictures, Rovio).  
**Открытые вопросы:**
1. Готов ли владелец продукта нести риски получения претензий правообладателей (DMCA / ст. 1270 ГК РФ) и возможной блокировки публичного хостинга?
2. Следует ли полностью убрать коммерческие JAR из публичного доступа, оставив в каталоге только легальные Homebrew-игры и демосцену, а коммерческие игры запускать исключительно через пользовательский Sideloading (локальный выбор JAR-файла с диска)?
3. Либо проект позиционируется как закрытый некоммерческий архив для исследователей истории видеоигр с доступом по авторизации?

## 2. Судьба серверного дуализма (Python vs Rust)

**Проблема:**  
В репозитории `j2me_market` сосуществуют `run_market.py` и `server_rust`.  
**Открытые вопросы:**
1. Целесообразно ли полностью удалить `run_market.py` из корня проекта, чтобы исключить путаницу разработчиков и рассинхронизацию проверок безопасности?
2. Является ли требованием возможность запуска платформы разработчиками без установленного тулчейна Rust (на «голом» Python)? Если да, то необходимо внедрить единый конфигурационный файл для обоих серверов.

---

## 3. Глубина реализации Mobile 3D Graphics (M3G / JSR-184)

**Проблема:**  
Такие культовые тайтлы, как *Deep 3D*, *Stalker Mobile*, *Galaxy on Fire 3D*, требуют полноценного 3D-конвейера M3G (матричные трансформации вершин, текстурирование полигонов, Z-буфер, расчет освещения). Сейчас в эмуляторе реализованы только заглушки (стабы) классов `javax.microedition.m3g`.  
**Открытые вопросы:**
1. Следует ли инвестировать инженерные ресурсы в полноценный программный растеризатор M3G на Rust (или трансляцию в WebGL вызовы)?
2. Либо фокус проекта должен оставаться на эталонной совместимости со 100% 2D-каталога MIDP 2.0 / Nokia UI?

---

## 4. Облачная синхронизация сохранений (Cloud RMS)

**Проблема:**  
В настоящее время сохранения в WebAssembly хранятся в `localStorage` конкретного браузера. Если пользователь играет с телефона, а затем открывает сайт на десктопе, его игровой прогресс не синхронизируется.  
**Открытые вопросы:**
1. Требуется ли введение легковесной системы учетных записей (или синхронизации по анонимному токену / QR-коду) для межплатформенного переноса сохранений RMS?
2. Каковы требования к срокам хранения и лимитам объема данных на сервере?

---

## 5. Мобильный WebAudio Unlock на iOS Safari

**Проблема:**  
Политика мобильного WebKit (iOS Safari) требует явного пользовательского жеста (User Gesture) для разблокировки `AudioContext`. В некоторых версиях iOS при переключении между играми или открытии модальных окон контекст может спонтанно переходить в состояние `interrupted` или `suspended`.  
**Открытые вопросы:**
1. Требуется ли внедрение нативного Web Gamepad / Haptic API виброотклика на поддерживаемых Android-устройствах?
2. Каков приоритет тестирования на старых мобильных устройствах с ограниченным объемом памяти WebAssembly (iOS 15–16)?
