## Phase 1: Безопасность и унификация бэкенда (1–2 недели)
1. **Унификация бэкенда J2ME Market:**
   - Перенести валидацию `Host` заголовка (защита от DNS Rebinding) и проверку `Sec-Fetch-Site` (защита от CSRF) из `run_market.py` в `server_rust/src/router.rs`.
   - Назначить `server_rust` единственным каноническим сервером. В документации закрепить команду `cargo run -p server_rust`.
2. **Изоляция серверных сохранений:**
   - Разделить хранение RMS на сервере по сессиям: `rms/sessions/<session_id>/<slug>/`.
   - Внедрить валидацию `X-Session-Token` для всех мутирующих запросов.

---

## Phase 2: Юридическая чистота и архитектура контента (BYOR) (2–3 недели)
1. **Закрытие публичной раздачи коммерческих ROM:**
   - Отключить в Nginx прямой алиас `location /roms/`.
   - Перевести публичный каталог на безопасную модель:
     - Включение в каталог свободных Homebrew-игр с открытыми лицензиями;
     - Реализация в интерфейсе функции **«Перетащите свой JAR» (Drag-and-Drop Sideloading)**: клиент загружает файл игры со своего компьютера напрямую в память браузерного эмулятора без сохранения на сервере.
2. **Публичный релизный пакет:**
   - Автоматизировать генерацию «чистого» дистрибутива `scripts/build_release.py` без проприетарных ROM.

---

## Phase 3: Автоматизация CI/CD и дифференциальной верификации (2–4 недели)
1. **GitHub Actions CI/CD Pipeline:**
   - Создать workflow для автоматической компиляции Rust-ядра под нативный таргет и WebAssembly (`wasm32-unknown-unknown`).
   - Автоматически публиковать и версионировать сборки WASM в `market_ui/wasm/` с генерацией `RELEASE_METADATA.json` (SHA-256 хеши, дата, коммит).
2. **Headless E2E тестирование в браузере:**
   - Добавить прогон сценариев запуска игр в реальном headless Chromium/Firefox через Playwright для проверки взаимодействия Canvas, AudioContext и WASM.
3. **Дифференциальный тест-сьют:**
   - Запуск ночного фаззера на пуле из 100 игр с автоматическим сопоставлением скриншотов FreeJ2ME и Rust J2ME Emulator по метрике SSIM.

---

## Phase 4: Оптимизация производительности тяжелых игр (4–6 недель)
1. **Рефакторинг NativeBridge:**
   - Разбить монолитный файл `native_bridge.rs` (10,695 строк) на модули по подсистемам: `cldc/`, `lcdui/`, `media/`, `nokia/`.
   - Заменить линейный `match` на хэш-таблицу указателей на функции для критических нативных вызовов, что снизит задержки в играх уровня God of War.
2. **Оптимизация рендеринга:**
   - Для мобильных браузеров внедрить WebGL2 текстурный блиттинг кадрового буфера с аппаратным билинейным/CRT фильтром, снизив нагрузку на композитор страницы.
