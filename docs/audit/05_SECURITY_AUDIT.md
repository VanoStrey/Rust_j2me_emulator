# 05. Аудит информационной безопасности (Security Audit)
## Модель угроз, анализ уязвимостей, изоляция песочницы и безопасность данных

---

## 1. Модель угроз и границы доверия (Threat Model)

Система обрабатывает потенциально недоверенный входной контент:
1. **Произвольные архивные файлы JAR/JAD:** Могут содержать вредоносный или обфусцированный байткод Java, эксплойты к парсерам ZIP/ClassFile, бесконечные циклы или попытки вызова недопустимых нативных функций.
2. **Сетевые HTTP-запросы пользователей:** Запросы к веб-интерфейсу, параметрам запуска эмулятора, передаче клавиш ввода и экспорту/импорту сохранений.
3. **Хранилище сохранений Record Management System (RMS):** Бинарные данные сохранений игр.

---

## 2. Анализ исполнения недоверенного байткода

### 2.1. Браузерная среда (WebAssembly Sandbox)
- **Изоляция:** Байткод гостевой Java-машины исполняется внутри виртуальной машины WebAssembly браузера.
- **Доступ к ресурсам:** У WASM-модуля отсутствуют системные вызовы операционной системы (нет прямого доступа к файловой системе хоста, реестру, процессам или локальным сокетам).
- **Сетевые соединения:** В крейте `j2me-stdlib` класс `javax.microedition.io.Connector` для протоколов `http://` и `socket://` либо заглушен безопасными стабами, либо маршрутизируется через контролируемые fetch-запросы с соблюдением браузерного CORS.
- **Защита от отказа в обслуживании (DoS):**
  - Аллокации памяти через `emu_alloc_buffer` жестко ограничены лимитом в 64 МБ. Попытка выделить буфер большего размера отклоняется возвратом нулевого указателя.
  - В интерпретаторе байткода внедрен счетчик непрерывных обратных переходов: при 50,000 непрерывных итераций цикл принудительно уступает квант времени браузеру, предотвращая зависание вкладки.

### 2.2. Серверная среда (Headless FreeJ2ME Process Isolation)
- При аварийном переключении на облачный стриминг сервер запускает изолированный процесс `java -Djava.awt.headless=true ... org.recompile.freej2me.WebBridgeRunner`.
- **Защита на уровне операционной системы:**
  - В системном сервисе systemd (`/etc/systemd/system/j2me.service`) включены флаги изоляции:
    - `NoNewPrivileges=true`
    - `PrivateTmp=true`
    - `ProtectSystem=full`
    - `ProtectHome=true`
    - `ProtectKernelTunables=true`
    - `ProtectControlGroups=true`
    - `RestrictRealtime=true`
    - `RestrictSUIDSGID=true`
- **Защита от инъекции команд:**
  - Параметр `slug` в `router.rs` проверяется на отсутствие спецсимволов командной строки, пробелов, обратных слешей и null-байтов. Путь к JAR-файлу формируется программно из белого списка известных директорий.

## 3. Детальный реестр уязвимостей и статус их устранения

### 3.1. [P1] Reflected XSS в Server-Side Rendering (`/issue/:id`) — ИСПРАВЛЕНО
- **Файлы:** `server_rust/src/router.rs`, `server_rust/src/ssr.rs`
- **Механизм возникновения:**  
  Эндпоинт `/issue/:id` извлекал подстроку после `/issue/` без валидации и напрямую подставлял её в шаблон страницы:
  ```rust
  let page_title = format!("«Страна Игр» — Выпуск {} • Подшивка 1996-2006", raw_id);
  let page_url = format!("https://177-3-222-50.sslip.io/issue/{}", raw_id);
  let route_json = format!(r#"{{"type":"issue","issueId":"{}"}}"#, raw_id);
  ```
  В файле `ssr.rs` значение `route_json` подставлялось в скрипт:
  `<script>window.INITIAL_ROUTE = {route_json};</script>`.  
  Согласно стандарту HTML5 (Script data state), последовательность `</script>` внутри тега `<script>` немедленно прерывает блок скрипта даже внутри строкового литерала JavaScript.
- **Вектор атаки:**
  Запрос: `/issue/%3C/script%3E%3Cscript%3Ealert(document.domain)%3C/script%3E`
- **Фактический результат до исправления:**  
  Инъекция выполнялась в контексте сайта, позволяя перехватывать токены, сохранения и манипулировать DOM.
- **Реализованное исправление:**
  1. В `router.rs` добавлен фильтр, требующий строгого соответствия шаблону номера выпуска: `raw_id.starts_with("issue_") && raw_id.len() == 9 && raw_id[6..].chars().all(char::is_ascii_digit)`. Любые иные значения приводят к ответу `404 Not Found`.
  2. В `ssr.rs` реализовано HTML-экранирование для всех текстовых полей и безопасное экранирование `</` в `<\/` для внедряемых JSON-блоков.
  3. Добавлен автоматический тест `test_ssr_xss_prevention_in_title_and_meta` в составе набора тестов `cargo test` сервера.

### 3.2. [P1] Отсутствие аутентификации и изоляции сохранений в `/api/rms/import` — ИСПРАВЛЕНО НА КЛИЕНТЕ, РЕКОМЕНДАЦИЯ ДЛЯ СЕРВЕРА
- **Файл:** `server_rust/src/router.rs` (строки 148–204)
- **Проблема:**  
  Эндпоинт `/api/rms/import` принимает JSON с сохранениями для указанного `slug` и сохраняет их в директорию `rms/<folder_name>/` на сервере.
  При этом проверка токена сессии или привязки к конкретному пользователю отсутствует. В результате сохранения одного игрока перезаписывают сохранения других игроков, играющих через серверный стрим.
- **Статус в клиенте:** В основном режиме (WASM) сохранения изолированы локально в `localStorage` каждого пользователя браузера (`j2me_rms_<slug>`).
- **Рекомендация для сервера:** Изолировать серверные папки по `session_id`: `rms/sessions/<session_id>/<slug>/`.

### 3.3. [P2] Проверка безопасности HTTP-заголовков (DNS Rebinding & CSRF)
При прогоне автоматического набора тестов безопасности `scripts/test_security.py` против продакшн-сервера `server_rust`:
- **Host Header:** `server_rust` не сверяет заголовок `Host` с белым списком доменов, полагаясь на фильтрацию внешнего Nginx (`server_name 177.3.222.50 177-3-222-50.sslip.io`).
- **Origin & Sec-Fetch-Site:** В `run_market.py` была реализована проверка `Origin == Host` и блокировка `Sec-Fetch-Site: cross-site`. В `server_rust` эта проверка отсутствовала ввиду открытого API.
- **Рекомендация:** Включить встроенную валидацию заголовка `Host` непосредственно в `server_rust/src/router.rs` в качестве второго эшелона защиты (Defense in Depth).

### 3.4. [P3] Защита от Path Traversal
- **Файл:** `server_rust/src/util.rs` (`serve_file_secure`)
- **Статус: БЕЗУПРЕЧНО (VERIFIED & TESTED)**
  - Реализована каноникализация путей через `canonicalize()`.
  - Проверяется строгое вхождение канонического пути файла в канонический путь базовой разрешенной директории: `canonical.starts_with(&base_canonical)`.
  - Заблокированы попытки обхода через `..`, `%2e%2e`, обратные слеши `\` и нулевые байты `\0`.
  - Заблокирован доступ к скрытым файлам и папкам, начинающимся с точки (`.git`, `.env`).
  - Проверено тестом `test_serve_file_secure_blocks_traversal_and_hidden`.
